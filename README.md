# LAB EX20 - GitHub Repository and Version Control

## Project Description

This project demonstrates GitHub repository management,
branching, pull requests, code review, merging, and
conflict resolution.

## Team Project

This repository was created to demonstrate collaborative
software development using Git and GitHub.

## Branches

### main
Contains the stable and final version of the project.

### frontend
Used for developing the frontend module.

### backend
Used for developing the backend module.

## Version Control Workflow

1. Created a GitHub repository.
2. Created separate branches for individual modules.
3. Developed the modules independently.
4. Committed changes using Git.
5. Pushed branches to GitHub.
6. Created Pull Requests.
7. Performed code reviews.
8. Merged approved branches into the main branch.
9. Created a merge conflict intentionally.
10. Resolved the merge conflict manually.
11. Updated the README to document the workflow.

## Pull Request and Code Review

The frontend and backend branches were submitted
through Pull Requests to the main branch.

Before merging, the changes were reviewed and approved.

## Conflict Resolution

A merge conflict was intentionally created by modifying
the same section of README.md in the main and frontend
branches.

The conflict was resolved manually by selecting the
required content and removing the Git conflict markers.

The resolved file was then added, committed, and pushed
to the main branch.

## Git Commands Used

- git clone
- git status
- git branch
- git checkout
- git add
- git commit
- git push
- git pull
- git merge

## Conclusion

This project demonstrates the use of GitHub for
collaborative software development through branches,
commits, Pull Requests, code reviews, merging, conflict
resolution, and documentation.
